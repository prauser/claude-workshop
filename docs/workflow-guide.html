베타 워크플로우 핸드북

spec‑plan → impl

사람과 합의된 계획(plan)을 만들고, 그 계획을 작은 task로 쪼개 구현·리뷰·통합한다. AI가 의도를 조용히 바꾸거나 게이트를 우회하지 못하게 막고, 모든 결정에 증거를 남긴다.

읽기전용 계획 위임 기반 구현 게이트 합의 증거 + 텔레메트리
01

명령 4종

무게중심은 /spec-plan · /impl. 나머지 둘은 1회성 설정·관리.

/spec-plan {TICKET}
티켓·요청 → 합의된 계획. 모든 서브에이전트 읽기전용, 코드 안 씀.
게이트 기반 · 계획만
/impl {TICKET}
계획 → 구현. 직접 코딩 안 하고 전문 에이전트에 위임.
오케스트레이션 · 위임

어휘 관리
02

전체 흐름

계획은 게이트로 합의되고, 구현은 위임으로 굴러간다. 붉은 노드 = 사람 승인 지점.

/spec-plan — 계획 (읽기전용)
준비도 점검› grill 정련› 컨텍스트 수집 ×5› Gate 0 정렬› Gate 1 요구› Gate 2 계획·모호점› Gate 3 테스트› plan.md
/impl — 구현 (위임)
plan.md 로드› task 분해› implementer› reviewer↻ needs-fix 최대 3R› commit› integrator
이해 마찰은 한 곳에. Gate 0·1·3은 bare OK로 가볍게 — 내용 정렬은 grill align diff와 cross-review가 검증한다. 복사로 못 뚫는 단일 프로브는 Gate 2 Spec Preview 한 곳에 집중: "맞다" 복붙이 아니라 화면에 없는 걸 답하게 한다(why-not / 예측 / 범위 판정).
03

공통 장치

두 명령이 공유하는 SSOT. 변경하면 ./deploy.sh로 ~/.claude/에 반영.

grill

한 번에 한 질문

모호한 입력을 멀티턴 인터뷰로 좁힌다. 4 mode(align·refine·elicit·grill), 웨이브 최대 3, 정렬되면 조기 종료.

preamble §8

위험영역 회피 금지

memory·replication·concurrency·architecture·build-deploy에 닿으면 [!CAUTION] 박스 강제. 회피 불가.

preamble §9

한글 순화

자연 대응어가 있으면 한글로(예: stale→오래된), 첫 약어는 한 줄 풀이. 우선순위: GLOSSARY › §9 › 휴리스틱.

04 · 핵심

산출물 7 카테고리 — 왜 필요한가

계획·코드 외에 강제되는 메타데이터. 얼핏 과해 보이지만 각각 특정 실패 모드를 막는다. 카테고리별로 분리해 확인하라.

A의도 보존
AI가 사용자 의도를 조용히 의역하지 못하게 잠근다. 원문이 task마다 복사돼 기준점이 사라지지 않음.
막는 실패의도 표류 — 그럴듯하지만 내가 원한 게 아닌 걸 정확히 구현, 끝나서야 발견
user_promptrefined_user_promptintent.problemintent_historyintent_problemcontributes_to
B게이트 텔레메트리
합의가 얼마나 매끄러웠는지·어디서 우회했는지 숫자로 남긴다. 워크플로우 자체를 개선하기 위한 계기판.
막는 실패죽은 게이트 — 다들 "ok"로 스킵해 정렬 장치가 형식만 남는 것
gate_events.turnsgate_events.probeskip_presearchskip_gate2readiness_flagsgate2-comprehension-incomplete
C위험 관리
위험영역에 닿으면 회피·은폐 못 하고 띄워 확인받는다. needs_check면 status를 partial로 강등.
막는 실패위험 은폐 — 위험 코드를 말없이 바꾸거나 "범위 밖"으로 회피
risk_areasrisk_acks[!CAUTION]
D어휘 일관성
같은 개념을 매번 다른(또는 영어) 단어로 쓰지 않게. 어쩔 수 없이 어긴 어휘는 사람이 볼 큐에 쌓는다.
막는 실패용어 표류 — 영어 범벅으로 주니어가 못 읽음
idiom_candidatesidiom-poolGLOSSARY hit
E추적성 · 드리프트
구현 중 계획이 바뀌면 task가 옛 계획대로 굴러가는 걸 감지해 알린다.
막는 실패계획 표류 — 끝나고 보니 plan과 코드가 따로 노는 것
plan_shaplan_deviations
F증거
"됐다"는 주장에 실행 가능한 근거를 붙인다. diff의 모든 변경 파일은 task가 선언·검증해야 함.
막는 실패검증 불가 완료 — "테스트 통과"라는 말만 있고 흔적이 없음
AC = bashtest-output.logdiff.patchstatus 머신manifest · quality_gates
G품질 라우팅
리뷰 지적을 우선순위로 분류해 차단급(p1·p2)만 되돌린다. p3·p4는 follow-up으로 흘림.
막는 실패무한 핑퐁 — 사소한 nit까지 고치느라 비용 폭발
p1–p4side_effectintent_check
핵심. 이 7개는 "관료주의"가 아니라 7개의 안전망이다. 각 칸은 위에서 봤던 한 가지 실패를 막는다 — 피드백을 줄 때 "이 안전망이 실제로 작동했나?"를 기준으로 보면 된다.
