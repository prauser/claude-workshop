승인 게이트 이해도 강화

게이트를 "OK 눌렀나"에서 "제대로 이해하고 승인하나"로 — 위험한 곳만 무겁게.

한눈에

TL;DR — spec-plan/impl에 "사람이 제대로 이해하고 승인"하도록 돕는 레이어를 더한다. 90%는 에이전트가 마크다운을 쓰는 방식을 바꾸는 상시(light) 처방이고, teach-back 같은 무거운 처방은 위험영역에서만 발동한다. 새 명령은 안 만들고 기존 게이트에 흡수.
핵심 진단. 현재 승인 조건은 "사용자가 OK라고 입력했는가"(spec-plan.md:53). 그러나 원칙은 "이해 못 하면 내 코드가 아니다". 게이트가 컴플라이언스는 검사하지만 이해도는 검사하지 않는다 — 이게 최대 레버리지 지점.

Friction Dial

모든 이해 보조가 "위험영역만 무겁게" 다이얼에 둘로 갈린다.

상시 LIGHT 쓰기 규율

  • Intent Header
  • BLUF / 표 / 체크리스트
  • 용어집 + 인라인 풀이
  • 구체 file:line 링크
  • 관용구 자동 순화 · 자기-순화 패스

비용 ≈ 0 · 항상 적용

위험영역 HEAVY 상호작용 확인

  • Mermaid 클래스/호출 다이어그램 + before/after diff
  • teach-back (스코프 본인 말로 재진술)
  • Ambiguity 항목별 read-back (sequential grill)
  • 사람이 쓴 설계노트
  • analyzer/reviewer 항상 + 위험유형별 quality gate

마찰↑ · 위험영역에서만

위험영역 정의 (가이드라인 §3) & 태깅

메모리(GC/포인터 수명) · 리플리케이션 · 동시성(GameThread vs 비동기) · 아키텍처 결정 · 빌드/배포.

하이브리드 (d) 태깅: CLAUDE.md risk_areas: 선언을 baseline → AI가 후보 추가 플래그 → 사람은 상향만 쉽게(하향 어렵게). false-negative 쪽으로 안전하게 기움.

작업 Phase

명령/에이전트 편집은 claude-config/ → 후 ./deploy.sh

Phase 1 — 상시 쓰기 규율 1순위

  • Intent Header (spec-plan plan.md + Gate 1)
  • 출력 구조화 (BLUF·[!WARNING]·<details>)
  • 구체 file:line + GitHub permalink

Phase 2 — 용어집 & 언어

  • CONTEXT.md + glossary_path
  • 부트스트랩(코드/PRD 추출 → confirm)
  • 인라인 풀이 · 관용구 순화 · 자기-순화

Phase 3 — grill 통합

  • Gate 0 align (상시)
  • Pre-search grill (조건부)
  • /impl free-text 업그레이드 (impl.md:79)

Phase 4 — 위험영역 다이얼

  • risk_areas: 선언
  • AI 태깅 + 사람 상향
  • heavy 처방 + analyzer Mermaid

Phase 5 — (선택) 보너스

  • debugger 가설-선택 게이트
  • PR 본문 빈칸 스캐폴드
  • HTML export (장수 문서만)
